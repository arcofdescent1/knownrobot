## Public comment

This is a particularly useful failure report because it already separates the demonstrated action range from the policy-predicted range and records the real-robot outcome instead of reporting only training loss.

For a durable reproduction record, the remaining pieces I would preserve before the current training attempt changes state are:

- immutable dataset and checkpoint revisions rather than mutable local paths;
- the exact preprocessor and postprocessor files used at rollout, including their hashes;
- observation/action feature names, ordering, units and shapes;
- calibration revision and the absolute-versus-relative action convention;
- per-joint normalization statistics from the training dataset;
- the same sampled frames run through both the training-time and rollout-time processing paths; and
- a trial ledger that retains the 0–1/3 outcomes, interventions and out-of-range pan excursions.

Those details would help distinguish dataset coverage, processor mismatch, normalization collapse and closed-loop distribution shift without treating any one diagnosis as established prematurely.

I work on KnownRobot, an open registry for robot-policy reproducibility evidence. If you are comfortable with it, may we prepare an attributable failure-record draft from this issue, pinned only to immutable artifacts you identify? We would label every result as author-reported, state that KnownRobot did not execute the policy, and return the exact draft for your correction before publication. A yes here—or an immutable dataset/checkpoint link—is enough to proceed; no response will not be treated as permission.
